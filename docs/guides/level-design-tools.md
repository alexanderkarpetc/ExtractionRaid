## 1. Для чого потрібні інструменти

**Environment Scatter** розставляє вибрані prefab у прямокутній області. Він знаходить поверхню, перевіряє правила розміщення та створює групу сценових об'єктів. Дизайнер може змінювати seed, переглядати варіанти, видалити результат або залишити його через Bake.

**Map Analysis** ставить віртуальні точки на наявний NavMesh і вимірює оточення: відстані до геометрії, cover і POI, кількість об'єктів та локальну прохідність. Результат відображається у Scene View. Аналізатор не змінює рівень і не визначає автоматично, чи хороший його дизайн.

Обидва інструменти працюють тільки в Unity Editor. Їхні скрипти не потрібно додавати на GameObject. Вони не додають систем аналізу або генерації в runtime. Створені Scatter об'єкти, однак, є звичайним вмістом сцени й мають звичайну вартість рендерингу, фізики та компонентів у грі.

## 2. Підготовка сцени та запуск

Відкрий звичайну сцену рівня, збережи її та дочекайся завершення компіляції. Працюй поза Play Mode і поза Prefab Mode.

Вікна доступні через:

- `Tools → Level Design → Environment Scatter`;
- `Tools → Level Design → Map Analysis`.

Верхня частина кожного вікна прокручується. Трикутник біля `Area`, `Prefabs`, `Element 0`, `POIs` та інших складених полів розкриває їхній вміст. `Element 0` — це запис списку, а не ознака помилки. `+` додає запис, `−` видаляє вибраний запис. Після додавання перевір значення: Unity може скопіювати попередній елемент списку.

### Що має бути у сцені

| Завдання | Потрібна підготовка |
|---|---|
| Scatter на землю | У поверхні є активний non-trigger Collider, а її layer входить у Ground Layer Mask. |
| Не перетинати будівлі та props | У перешкод є активні non-trigger Collider, а їхні layers входять у Collision Layer Mask. |
| Exclusion zone | Активний Collider, який охоплює заборонену область на висоті землі. Trigger дозволений. |
| Avoid NavMesh | У сцені завантажений побудований NavMesh. |
| Map Analysis | Побудований NavMesh, правильний Agent Type Id і вибрані layers геометрії. |
| Відстань до POI | Активні сценові об'єкти, явно додані до списку POIs. |

**Layer Mask працює з Unity Layer, а не з Tag.** Назва об'єкта `Cover`, тег `Cover` чи папка `Cover` самі по собі нічого не змінюють.

Layer перевіряється на GameObject, де знаходиться відповідний Renderer або Collider. Якщо layer призначений лише порожньому parent, а дочірня геометрія лишилася на іншому layer, результат може відрізнятися від очікуваного. Перевір саме дочірні об'єкти з компонентами.

Обирай наявні layers проєкту свідомо. Зміна layers у сцені може також впливати на камери та gameplay physics; інструменти не створюють і не переналаштовують layers автоматично.

## 3. Область Area та Scene Handles

Обидва інструменти мають власну незалежну область. Перенесення області Scatter не пересуває область Map Analysis.

| Поле | Значення |
|---|---|
| Center | Світова позиція центра: X/Y/Z. |
| Size → X | Повна ширина прямокутника по його локальній X. |
| Size → Y | Повна довжина прямокутника по його локальній **Z**. Поле назване Y, бо розмір зберігається як Vector2. |
| Rotation Y | Поворот прямокутника навколо світової вертикалі, у градусах. |
| Show Area | Показувати блакитну рамку у Scene View. |
| Edit Area Handles | Показувати маніпулятори переміщення, повороту та розміру. |

Наприклад, `Center = (100, 0, 50)`, `Size = (40, 20)`, `Rotation Y = 0` задає область від X=80 до X=120 і від Z=40 до Z=60. Це повні розміри, не радіуси.

Щоб налаштувати область мишею, увімкни одночасно `Show Area` і `Edit Area Handles`, потім працюй у Scene View. Вертикальний масштаб маніпулятора не створює висоту коробки: область залишається площиною XZ. Зміни handles підтримують Undo.

Для Scatter `Center.Y` визначає середину вертикального пошуку землі. Для Map Analysis це висота, біля якої шукається NavMesh. На нерівній або багатоповерховій карті це важливий параметр.

Окремого `Scatter Area Object` або компонента області немає. Вибір об'єкта в Hierarchy автоматично не переносить область на нього — координати задаються полями або handles.

## 4. Scatter: перша генерація

1. Відкрий `Environment Scatter` у збереженій сцені.
2. Розкрий `Area` і розмісти невелику область над видимою землею, наприклад 20 × 20 одиниць.
3. Розкрий `Prefabs`, натисни `+`, потім розкрий `Element 0`.
4. У поле `Prefab` перетягни **кореневий prefab asset із Project**, а не його instance з Hierarchy і не дочірній об'єкт prefab.
5. Залиш `Enabled` увімкненим, `Weight` додатним, а обидва per-prefab Scale — 1.
6. Для першої перевірки задай `Target Object Count = 20`, `Global Min Distance = 1`, глобальний Scale = 1.
7. У `Ground Layer Mask` вибери layer землі. На землі має бути Collider. Для простого старту не вмикай `Avoid NavMesh`.
8. Залиш `Avoid Collisions` увімкненим і вибери layers перешкод у `Collision Layer Mask`.
9. Натисни `Generate Preview` і прочитай статус унизу.
10. Знайди `EnvironmentScatter_PREVIEW` у Hierarchy. Оглянь об'єкти зверху та збоку.
11. Спробуй `Randomize Seed`. Якщо результат влаштовує — `Bake`; якщо ні — `Clear Preview`.

Не починай одразу з тисяч важких prefab. Спочатку переконайся, що поверхня, масштаб моделей і masks налаштовані правильно.

## 5. Scatter: усі параметри

### Prefabs

| Поле запису | Що робить |
|---|---|
| Prefab | Активний кореневий prefab asset. Для grounding і collision потрібні ненульові bounds активного Renderer. |
| Enabled | Дозволяє вибирати цей запис. Вимкнений запис залишається у списку, але не бере участі. |
| Weight | Відносна ймовірність вибору. Нульова або від'ємна вага не бере участі. |
| Scale Min / Scale Max | Діапазон додаткового рівномірного масштабу саме цього prefab. Значення мають бути додатними. |
| Allow Rotation Y | Дозволяє додавати випадковий yaw цьому prefab, якщо глобальний Random Rotation Y теж увімкнений. |
| Min Distance Override | Від'ємне значення, наприклад −1, використовує глобальну дистанцію. Нуль або додатне значення задає власну дистанцію. |

Вага — не кількість. Для трьох записів із вагами 6, 3 і 1 імовірності вибору на спробі приблизно 60%, 30% і 10%. У готовому результаті пропорції можуть відрізнятися: великий prefab частіше відхиляється через collision або нестачу місця. Точні квоти інструмент не гарантує.

Мінімальна дистанція перевіряється між точками посадки нових об'єктів у XZ. Для пари діє **більша з двох дистанцій**. Якщо для каменя встановлено 0.5, а для автомобіля 5, між їхніми точками посадки потрібно щонайменше 5. Це не відстань між краями моделей. Звичайні старі об'єкти та попередні baked-групи враховуються collision check, а не цим правилом дистанції.

### Placement

| Поле | Як використовувати |
|---|---|
| Target Object Count | Скільки об'єктів потрібно отримати. Це ціль, яка може виявитися недосяжною за поточних обмежень. |
| Seed | Ціле число, що задає послідовність випадкових рішень. |
| Global Min Distance | Базова мінімальна відстань для записів без override. Не масштабується разом із prefab. |

Режиму Density для Scatter зараз немає. Щоб отримати щільніше заповнення, змінюй count, площу або допустиму дистанцію.

Однаковий seed відтворює результат за незмінних налаштувань, порядку prefab list, prefab assets і стану сцени. Зміна землі, перешкод, exclusion zones або NavMesh може змінити результат навіть із тим самим seed.

### Rotation and scale

| Поле | Значення |
|---|---|
| Random Rotation Y | Вмикає додаткове випадкове обертання навколо Y. Потрібен також Allow Rotation Y у записі. |
| Rotation Min / Rotation Max | Межі випадкового кута в градусах. Однакові межі задають сталий додатковий кут. |
| Global Scale Min / Global Scale Max | Спільний діапазон множника масштабу. Множиться на per-prefab scale та початковий scale asset. |

Для масштабу діє така послідовність: початковий scale prefab × випадковий глобальний множник × випадковий множник запису. Наприклад, при початковому scale 1, глобальному множнику 1.1 і множнику запису 0.8 результат буде 0.88. Це пояснення роботи, не окреме поле інтерфейсу.

Якщо потрібен лише один діапазон масштабу, залиш інший на 1…1. Випадковий множник однаковий для всіх осей, але початковий нерівномірний scale asset зберігається. Вимкнення Random Rotation Y не скидає авторський поворот prefab. Rotation Y області повертає саму область, а не автоматично всі props.

### Surface

| Поле | Значення |
|---|---|
| Raycast Height | Промінь починається на цю висоту вище Center.Y і проходить до такої ж відстані нижче Center.Y. |
| Ground Layer Mask | Layers Collider, які можуть бути поверхнею посадки. Trigger-колайдери ігноруються. |
| Max Ground Slope | Максимальний кут нормалі поверхні від вертикалі: 0 означає горизонтальну поверхню. |
| Align To Ground Normal | Додає нахил відповідно до нормалі знайденої поверхні. |

При Center.Y=10 та Raycast Height=30 пошук проходить від Y=40 до Y=−20. Для кожної випадкової XZ-точки береться найближчий hit зверху серед дозволених layers. Поточний Preview не використовується як земля.

Якщо включити у Ground Layer Mask також дахи, ящики та старі scatter props, об'єкти можуть з'являтися на них. Для розміщення саме на землі використовуй відповідний layer поверхні.

Grounding компенсує положення pivot за bounds моделі. Але bounds — це коробка навколо геометрії, а не точна форма її опори. На нерівному terrain, сходах або під моделлю з виступами потрібна перевірка збоку. Align To Ground Normal не деформує модель під terrain і не ставить кожну її ніжку окремо на землю.

### Collision

| Поле | Значення |
|---|---|
| Avoid Collisions | Перевіряти перетин із новими scatter objects та наявними Collider. |
| Collision Layer Mask | Layers наявних фізичних перешкод. Trigger-колайдери не блокують цей запит. |
| Collision Radius Multiplier | Множник ширини та довжини перевірочної коробки. Висота не збільшується. |

Значення multiplier більше 1 залишає більше вільного місця; менше 1 дозволяє щільніше розміщення й може допустити видимі перетини. Перевірка приблизна: між новими props застосовуються консервативні світові bounds, до наявної сцени — орієнтована коробка. Тому деякі геометрично можливі місця можуть бути відхилені.

Наявна модель без Collider не блокує Scatter, навіть якщо добре видима. Новий scatter prefab може не мати Collider: інструмент усе одно має його renderer bounds. Це не означає, що він після Bake почне блокувати гравця — gameplay collision залежить від компонентів prefab.

Вимкнення Avoid Collisions не вимикає Min Distance, slope, exclusions або NavMesh avoidance.

### Exclusion and NavMesh

| Поле | Значення |
|---|---|
| Exclusion Colliders | Явний список заборонених Collider. Можна перетягнути компонент або GameObject із Collider на самому об'єкті. |
| Exclusion Layer Mask | Заборонені зони, знайдені за layer. Trigger-зони також враховуються. |
| Avoid NavMesh | Відхиляти точку, якщо поблизу знайдено NavMesh. |
| NavMesh Avoidance Radius | Просторовий радіус пошуку NavMesh біля точки посадки. |

Для забороненого проходу створи через Editor GameObject із BoxCollider, розмісти його так, щоб об'єм перетинав рівень землі, і додай до списку. Для чисто дизайнерської зони можна використати trigger; переконайся, що його layer не обраний землею. Для явного списку використовуй primitive або convex Collider. Collider на дочірньому об'єкті краще перетягувати безпосередньо, а не його порожній parent.

Обидва способи exclusion доповнюють один одного: достатньо потрапити в будь-яку заборонену зону. Перевіряється **точка посадки**, а не весь контур prefab. Щоб довга машина не виступала в дорогу, розшир заборонений об'єм із запасом.

Avoid NavMesh не знаходить дороги за назвами й не розуміє, який прохід головний. Якщо весь майданчик покритий NavMesh, увімкнення цієї опції може відхилити всі точки. У Scatter немає окремого фільтра Agent Type Id або NavMesh Area Mask. Радіус просторовий: близький NavMesh на іншому поверсі теж може вплинути. Без завантаженого NavMesh ця перевірка нічого не відхилить.

### Safety

| Поле | Значення |
|---|---|
| Max Placement Attempts | Загальний бюджет кандидатів, разом із відхиленими. Після його вичерпання залишається отриманий результат. |
| Maximum Generated Objects | Дозволена верхня межа Target Object Count для одного запуску. |

Поточна реалізація обмежує count максимумом 10 000, а attempts — 1 000 000. Ці межі не є цільовими робочими значеннями. Великий бюджет спроб не створить місце там, де всі точки заборонені.

Статус `Preview ready: 140/500. Placement attempts exhausted…` означає, що вдалося створити 140 об'єктів, а решта спроб була витрачена. Перевір правила або зменш count. Це не автоматично помилка генератора.

## 6. Preview, Bake, Clear та Undo

| Дія | Результат |
|---|---|
| Generate Preview | Після успішної валідації замінює поточний tracked Preview новою генерацією. |
| Randomize Seed | Змінює seed і повністю генерує новий Preview. Старий варіант не залишається поруч для порівняння. |
| Clear Preview | Видаляє tracked Preview parent з усіма його дітьми. |
| Bake | Перейменовує tracked parent на EnvironmentScatter_BAKED та перестає вважати його Preview. |
| Cancel (keep partial result) | Зупиняє Scatter; уже створені об'єкти залишаються під Preview parent. |

Bake **не** об'єднує meshes, не створює LOD, не оптимізує матеріали, не будує NavMesh і не робить Unpack Prefab. Діти вже до Bake є звичайними сценовими GameObject; їхні prefab-зв'язки зберігаються й після Bake. Їх можна редагувати звичайними засобами Unity.

Інструмент зберігає посилання на один поточний Preview. Після Bake можна генерувати наступний шар: наприклад, спочатку каміння, потім кущі. Попередня baked-група не замінюється, але може блокувати нові точки через свої Collider. Назва групи сама по собі не керує її статусом: ручне перейменування Preview не замінює Bake, а довільна група з таким самим ім'ям не стає tracked Preview.

Якщо додати свої об'єкти під Preview parent, Clear Preview видалить і їх. Якщо вручну винести дитину з Preview parent, очищення групи вже не охопить її. Перед Bake не переміщуй частини Preview між групами без потреби.

### Як працює Undo

Налаштування, handles, розміщення, Clear та Bake підтримують Unity Undo. Окремі розміщення мають власні Undo-групи: один Ctrl+Z після генерації не обов'язково прибере всі props. Так реалізація не захоплює сторонні дії дизайнера між пакетами роботи.

Щоб видалити весь поточний варіант, натисни Clear Preview. Цю дію можна скасувати Undo. Undo Bake повертає Preview-стан групи. Історія Undo не є способом відновлення варіантів після перезапуску Editor.

Під час генерації поля блокуються. Cancel, Undo, закриття вікна або зміна Play Mode стану зупиняють роботу. Після скасування не вважай старий текст лічильника підтвердженням завершення: перевір фактичну кількість дітей у групі.

## 7. Практичні сценарії Scatter

### Дрібне сміття

Для навчальної області 20 × 20 спробуй count 50, Min Distance 0.5, Rotation 0…360, Global Scale 0.8…1.2. Per-prefab Scale залиш 1…1, додай кілька варіантів із різними вагами. Увімкни collisions і захисти основний прохід exclusion-зоною. Спочатку перевір кілька десятків об'єктів, потім збільшуй count.

### Кущі та каміння біля проходу

Задай область уздовж його краю. Для кущів установи більшу дистанцію, ніж для дрібного каміння. Основний прохід закрий BoxCollider exclusion-зоною з запасом під габарити моделей. Avoid NavMesh вмикай лише тоді, коли заборонена вся walkable-поверхня, а не тільки конкретний маршрут.

### Автомобілі або великі ящики

Почни з кількох об'єктів та великого Min Distance Override. Обмеж Rotation Min/Max, якщо потрібний певний напрямок, або вимкни випадковий поворот і використай авторський поворот prefab. Scatter не створює паркувальну сітку й не вирівнює об'єкти за фасадами. Остаточне положення великих props доцільно відредагувати вручну.

Для всіх сценаріїв: просторовий вигляд перевіряй у Scene View, а реальну прохідність і collision гравця — окремо у gameplay-перевірці.

## 8. Map Analysis: перший аналіз

1. Переконайся, що у сцені є побудований і завантажений NavMesh для потрібного agent type. Аналізатор не виконує його Bake.
2. Відкрий `Map Analysis` і розкрий `Area`.
3. Задай невелику область над NavMesh. Center.Y має бути близьким до поверхні навігації.
4. Для першої спроби використай Sample Spacing 3 і достатній для цієї ділянки Sample Height Tolerance.
5. Укажи правильний Agent Type Id. Це числовий ID типу агента, а не його порядковий номер у списку. Якщо ID невідомий, звір його з налаштуванням agentTypeID компонента NavMeshSurface, на якому побудована карта.
6. Залиш NavMesh Area Mask = −1, якщо потрібні всі доступні areas цього агента.
7. Вибери Interesting Layer Mask, Cover Layer Mask і Density Layer Mask. За початково порожніх masks геометрія не буде знайдена.
8. Додай POI до списку або вимкни POI Distance для першого аналізу.
9. Увімкни Show Visualization та Show Samples, вибери Overlay і натисни Analyze Map.
10. Дочекайся `Analysis ready`. Перевір кількість valid samples, потім перемикай overlays та натискай на точки.

Якщо NavMesh ще не побудований, це потрібно зробити наявним у проєкті процесом authoring. Наявності Renderer або землі з Collider недостатньо для Map Analysis.

## 9. Map Analysis: усі параметри

### NavMesh

| Поле | Значення |
|---|---|
| Sample Spacing | Бажаний крок grid у світових одиницях. Менший крок дає більше точок і більшу вартість аналізу. |
| Sample Height Tolerance | Максимальний дозволений вертикальний відступ NavMesh від площини запиту. |
| Agent Type Id | Числовий ID агента, чий NavMesh використовується. |
| NavMesh Area Mask | Цілочисельна бітова маска NavMesh areas. Це інша система, ніж Unity Layer Mask. −1 включає всі areas, 0 не включає жодної. |
| Maximum Samples | Ліміт кількості кандидатів grid до запуску аналізу. Жорстка верхня межа реалізації — 100 000. |

Для area index 0 біт маски дорівнює 1, для index 1 — 2, для index 2 — 4. Поєднання areas 0 і 2 дає 5. Це приклад бітової маски, не перелік areas конкретної карти. Якщо спеціальний фільтр не потрібний, використовуй −1.

Оцінка кандидатів дорівнює добутку округлених угору відношень ширини та довжини області до spacing. Для 60 × 60 при spacing 3 це 400 кандидатів. Valid samples може бути менше: точки без близького NavMesh відкидаються. Перевищення ліміту зупиняє запуск цілком; автоматичного урізання до Maximum Samples немає.

Точки розподіляються рівномірно всередині прямокутника; якщо розмір не кратний spacing, фактичний крок трохи коригується. Пошук допускає лише невеликий горизонтальний зсув до NavMesh. Тому біля країв або дуже вузьких проходів можуть бути пропуски. Збільшення Height Tolerance саме по собі не заповнює горизонтальні прогалини.

На похилій великій карті одна площина з малим висотним допуском може пропустити верхні й нижні ділянки. Розбий її на області або обережно зміни допуск. На багатоповерховій карті занадто великий допуск може вибрати не той поверх.

### Modules

| Toggle | Що обчислює |
|---|---|
| Empty Traversal | Відстань до interesting geometry та участь у пошуку порожніх кластерів. |
| Cover | Відстань до геометрії на Cover Layer Mask. |
| POI Distance | Відстань до найближчого POI зі списку. |
| Connectivity | Кількість доступних напрямків і flags potential dead end/corridor. |
| Object Density | Кількість відповідних об'єктів у радіусі. |

Вимкнений модуль не має актуальних вимірювань у новому результаті. Його overlay стає сірим. Якщо ввімкнути модуль після аналізу, натисни Analyze Map повторно.

### Empty traversal та Cover

| Поле | Значення |
|---|---|
| Interesting Layer Mask | Яку геометрію вважати змістовним оточенням для Traversal. |
| Traversal Thresholds → Warning / Bad | Межі кольорів для відстані до interesting geometry. |
| Cover Layer Mask | Яку геометрію умовно вважати потенційним cover. |
| Cover Thresholds → Warning / Bad | Межі кольорів для відстані до cover. |

Відстань вимірюється по XZ до краю bounds, а не до pivot і не вздовж шляху NavMesh. Для cover не перевіряються висота укриття, напрямок пострілу, матеріал, пробиття чи можливість присісти. Близька стіна може давати малу відстань, навіть якщо до неї треба обходити іншу перешкоду.

Порогова схема однакова для всіх distance overlays:

| Відстань | Категорія |
|---|---|
| Менше Warning | Good |
| Від Warning включно до Bad невключно | Warning |
| Від Bad включно | Bad |

Має виконуватися `0 ≤ Warning < Bad`. Наприклад, Warning=8 і Bad=15 означають: 7.9 — Good, 8 — Warning, 15 — Bad. Окреме поле Good не потрібне.

**Не включай суцільну землю в Interesting або Cover mask**, якщо хочеш вимірювати саме відстань до props і укриттів. Bounds землі можуть охоплювати всі samples і давати нульову відстань майже всюди.

### POI

У цій версії `MapAnalysisPOI` — запис даних у налаштуваннях, **не MonoBehaviour для Add Component**.

Щоб додати POI, створи або вибери сценовий GameObject у потрібній позиції, за потреби використовуй звичайний порожній marker. Збережи сцену. Розкрий POIs, додай запис і перетягни цей GameObject із Hierarchy у Scene Object.

| Поле | Значення |
|---|---|
| Scene Object | Активний об'єкт завантаженої сцени або його Component. Його transform визначає центр POI. |
| Poi Name | Зручна назва для дизайнера у списку. |
| Radius | Радіус POI у XZ. Відстань рахується до його краю; всередині дорівнює нулю. |
| Type | Major, Minor, Extraction, Spawn або Other. У поточній версії це описова категорія. |
| POI Thresholds → Warning / Bad | Спільні пороги відстані до найближчого POI. |

Poi Name і Type не змінюють вагу POI та не задають різні алгоритми. Фільтрації за типами, окремих порогів за типом і автоматичного пошуку extraction/spawn об'єктів немає. Інструмент також не малює окремо радіуси всіх POI.

При відстані 20 до центра й Radius=5 вимірювання становитиме 15. Це пряма XZ-відстань до радіуса, не довжина маршруту. Якщо модуль увімкнений, а жодного придатного POI немає, результат — `∞ (no target)`.

### Density

| Поле | Значення |
|---|---|
| Density Layer Mask | Геометрія, яка бере участь у підрахунку. |
| Density Radius | Радіус пошуку у XZ, відстань перевіряється до bounds. |
| Low Density Threshold | Найбільша кількість, що ще вважається Low. |
| High Density Threshold | Найменша кількість, що вже вважається High. |

Якщо Low=2 і High=9, то 0–2 — Low, 3–8 — Medium, 9 і більше — High. High має бути більшим за Low.

Renderer і Collider одного об'єкта не рахуються двічі. Геометрія об'єднується за найближчим prefab instance root; для об'єктів без prefab використовується сам GameObject. Тому prefab із десятьма звичайними дочірніми мешами може рахуватися як один об'єкт, а вкладені prefab можуть рахуватися окремо. Великий bounds може потрапити в радіус, навіть якщо pivot далеко.

Це кількість геометричних об'єктів за правилами групування, не відсоток заповненої площі, не кількість трикутників і не оцінка FPS. High density не означає автоматично добрий дизайн або прийнятну продуктивність.

### Connectivity та clustering

| Поле | Значення |
|---|---|
| Connectivity Radius | На якій відстані від sample перевіряти рух у кожному напрямку. |
| Dead End Max Directions | Максимальна кількість доступних напрямків, за якої ставиться PotentialDeadEnd. |
| Minimum Cluster Samples | Мінімальна кількість пов'язаних порожніх samples для великого маркера Long Empty Traversal. |

Перевіряються чотири світові напрямки: +X, −X, +Z, −Z. Кожен зараховується, якщо ціль має придатний NavMesh і прямий NavMesh.Raycast до неї не заблокований. Поворот Area не повертає ці чотири напрямки.

Це евристика. У діагональному вузькому проході вона може показати низьку connectivity, хоча прохід існує. Більший radius може частіше впиратися у стіни. Напрямки перевіряються і за межами Analysis Area, тому її край сам по собі не є стіною. Off-mesh links і довгі обхідні шляхи не враховуються.

PotentialDeadEnd залежить від Dead End Max Directions. Corridor ставиться при двох доступних напрямках. Зміна порога dead end не змінює фіксовану кольорову шкалу Connectivity overlay.

### Display

| Поле | Що змінює |
|---|---|
| Show Visualization | Показ або приховування всіх результатів. Area має окремий toggle. |
| Overlay | Основну метрику, що визначає колір samples. |
| Show Samples | Показ кольорових точок і кілець potential dead end. |
| Show Problem Areas | Великі кругові маркери порожніх кластерів. |
| Show Labels | Текст на великих маркерах. Не створює підпис кожної sample. |
| Maximum Drawn Samples | Бюджет відображення; за потреби показується проріджена частина готових samples. |
| Maximum Drawn Markers | Обмежує кількість великих маркерів. Першими йдуть кластери з більшою кількістю samples. |
| Good / Warning / Bad Color | Кольори відповідних категорій. |

Display-параметри можна змінювати без нового аналізу після завершення поточного запуску. Усі measurement-параметри, включно з thresholds, потребують повторного Analyze Map. До цього кольори залишаються відповідними налаштуванням останнього завершеного результату.

## 10. Як читати overlay та проблемні зони

### Основні режими

| Overlay | Що означає колір |
|---|---|
| Traversal | Категорію відстані до interesting geometry. Це не окрема карта лише Long Empty Traversal. |
| Cover Distance | Категорію відстані до умовного cover. |
| POI Distance | Категорію відстані до краю найближчого POI. |
| Object Density | Low використовує Bad Color, Medium — Warning Color, High — Good Color. |
| Connectivity | 0–1 напрямок — Bad Color, 2–3 — Warning Color, 4 — Good Color. |

Початково кольори зелений, жовтий і червоний, але дизайнер може їх змінити. Сірий означає, що відповідний модуль не обчислювався. `∞ (no target)` означає відсутність знайденої цілі, а не точно виміряну надзвичайно велику відстань. У density/connectivity інспекторі значення −1 означає відсутність обчислення.

### Long Empty Traversal

Кандидатом у порожній кластер є sample, для якої:

1. Empty Traversal увімкнений, а відстань до interesting geometry досягла Bad.
2. Якщо Cover увімкнений — відстань до cover теж досягла Bad.
3. Якщо POI Distance увімкнений — відстань до POI теж досягла Bad.
4. Якщо Object Density увімкнений — кількість об'єктів не перевищує Low Density Threshold.

Вимкнені додаткові модулі не беруть участі в умові. Без Empty Traversal ці кластери не утворюються. Connectivity не є обов'язковою умовою порожнього кластера.

Кандидати об'єднуються за сусідством grid у чотирьох напрямках лише за прохідного NavMesh-зв'язку. Якщо samples достатньо, з'являється великий круг і напис `LONG EMPTY TRAVERSAL`. Коло приблизне: воно може охоплювати простір за межами реальної форми кластера. Не сприймай його як точний полігон для забудови.

Число в дужках — кількість samples у кластері. Cover і POI у підписі — **найбільші відповідні відстані серед його samples**, не середні й не значення в центрі кола. Ці два максимуми можуть належати різним точкам. «Long» тут не означає обчислений час пробіжки або довжину маршруту.

Якщо маски порожні, а POI не задані, велика кількість червоних точок може означати незавершене налаштування аналізу. Спочатку перевір джерела даних.

### Клік та інспекція

Натисни лівою кнопкою біля кольорової sample у Scene View без Alt. У вікні з'являться її Position, Interesting/Cover/POI distances, Density, Connectivity та Flags. За сильного прорідження можна вибрати лише точки, що входять у display budget. Окремої інспекції кластерів кліком немає.

Біле кільце навколо точки — PotentialDeadEnd, незалежно від поточного основного overlay. Наприклад, зелена точка з білим кільцем може бути близько до cover, але мати малу локальну connectivity. Це різні вимірювання.

Результати малюються у Scene View з перевіркою глибини. Геометрія може їх закривати; поглянь зверху або зміни ракурс. У Game View цього overlay немає.

## 11. Робочий цикл дизайнера

1. Збережи поточний рівень і вибери конкретну ділянку роботи.
2. Налаштуй masks і POI, зроби початковий Analyze Map. Перевір не лише червоні зони, а й кілька числових samples.
3. Визнач, яку проблему потрібно вирішити: відсутність cover, довгий порожній простір, слабка орієнтація чи вузька прохідність.
4. Для декоративного заповнення зроби невеликий Scatter Preview. Для важливого бойового cover або великих POI використовуй усвідомлене ручне розміщення.
5. Перевір землю, проходи й композицію. Спробуй інші seed, потім Bake обраний результат.
6. Якщо зміни впливають на навігацію, онови NavMesh наявним процесом проєкту. Analyze Map сам цього не зробить.
7. Запусти Analyze Map повторно з тими самими порогами й masks. Порівняй показники в тих самих місцях. Вбудованого збереження двох результатів для порівняння немає.
8. Оглянь рівень із камери гри та перевір реальний рух. Після приймання збережи сцену.

Не заповнюй усі червоні ділянки однаковими дрібними props: це може збільшити density, не додавши корисного cover або змісту маршруту. Метрики потрібні для постановки запитань до ділянки, а не для автоматичного доведення всієї карти до зеленого кольору.

## 12. Збереження та продуктивність

### Що зберігається

Налаштування зберігаються у локальних EditorPrefs окремо для користувача та шляху проєкту. Закриття й повторне відкриття вікна не має скидати їх. Це не спільний asset preset: інший дизайнер або інша копія репозиторію може мати інші значення. Кнопок експорту, імпорту чи повного reset немає.

Посилання на prefab та сценові об'єкти зберігаються через GlobalObjectId. Для сценових об'єктів потрібна збережена сцена; після рестарту її треба завантажити. Для довготривалого використання новостворених exclusion/POI об'єктів збережи сцену після їх створення. Видалений об'єкт або незавантажена сцена можуть дати порожнє поле.

Preview і Baked-групи зберігаються як частина сцени. Preview не є автоматично виключеним із білда. Перед підготовкою рівня свідомо Bake або Clear його.

Map Analysis result — тимчасовий кеш вікна. Не покладайся на його збереження після закриття або рестарту: за потреби запускай аналіз знову. Clear Analysis прибирає samples та clusters; блакитна рамка Area може залишитися, доки ввімкнений Show Area.

### Як не перевантажити Editor

Працюй ділянками й окремими шарами Scatter. Вартість створення одного складного prefab із багатьма компонентами може бути значно більшою, ніж простого куба. Count сам по собі не прогнозує швидкодію.

Генерація та аналіз виконуються поступово через Editor update з коротким часовим бюджетом. Це не фоновий потік: окреме створення важкого prefab або побудова великого geometry index можуть тривати довше одного бюджету. Cancel обробляється між кроками роботи.

Для аналізу спочатку використовуй більший spacing і малу область. Зменшення spacing удвічі приблизно учетверо збільшує кількість кандидатів. Обмежуй Maximum Drawn Samples і Maximum Drawn Markers для зручності Scene View; це зменшує відображення, але не кількість вимірювань уже виконаного аналізу.

Geometry snapshot збирається з **усіх завантажених сцен**, а не лише зсередини Box Area. Область обмежує позиції samples. Об'єкт поза рамкою може бути найближчим cover або POI. Велика кількість завантаженої геометрії впливає на час її збору навіть для малої області.

Під час роботи уникай паралельної зміни сцени або запуску Scatter одночасно з Map Analysis: результати повинні відповідати одному зрозумілому стану карти. Автоматичного оновлення після змін сцени немає.

## 13. Усунення проблем

| Симптом | Що перевірити або зробити |
|---|---|
| Усі поля сірі | Прочитай статус: Play Mode, перехід до нього або Working блокують редагування. Дочекайся завершення або Cancel. |
| Поза Play Mode все сіре й написано Ready | У ранній версії був баг NotEditable. У поточному коді він виправлений. Дочекайся компіляції, закрий і повторно відкрий обидва вікна; якщо лишилось — перевір помилки Console. |
| Не видно Prefab поля | Розкрий Prefabs, а потім трикутник біля Element 0. |
| Enabled є, але Generate відхиляється | Потрібен активний root prefab asset із Project, додатна вага й придатні Renderer bounds. Перевір кожен увімкнений запис. |
| Save the scene first | Збережи активну сцену. Відкрита інша збережена сцена не замінює збереження активної. |
| Use a normal scene in Edit Mode | Вийди з Play Mode або Prefab Mode. |
| Target count exceeds Maximum Generated Objects | Зменш count або свідомо підніми Maximum Generated Objects у допустимих межах. |
| Preview порожній | Перевір Area, Center.Y, землю з Collider, Ground Layer Mask і slope; потім exclusions, collisions та Avoid NavMesh. |
| Отримано менше об'єктів, ніж задано | Прочитай attempts/status. Збільш область, зменш count або дистанцію, перевір розміри моделей і заборонені зони. |
| Props на дахах або інших ящиках | Ground Layer Mask включає ці поверхні. Виключи їх із маски землі. |
| Props перетинають стару геометрію | Перевір Collider перешкоди, його layer, Avoid Collisions і multiplier. Видимий mesh без Collider не блокує наявну сцену. |
| Props виглядають завислими | Оглянь bounds/pivot, схил, виступи моделі та нерівність поверхні. Grounding приблизний. |
| Exclusion не працює | Collider має бути активним, лежати на правильному layer або бути в списку й охоплювати висоту точки землі. Порожній parent із дочірнім Collider треба замінити прямим посиланням. |
| Машина виступає в exclusion zone | Правило перевіряє точку посадки. Розшир заборонену область під габарити. |
| Bake неактивний | Немає доступного tracked Preview; створи його або відкрий сцену, до якої належить збережене посилання. |
| Seed дає інший результат | Перевір порядок prefab list, scales, ваги, активність, scene geometry, exclusions і NavMesh; вони також визначають результат. |
| Analysis має 0 samples | Перевір наявний NavMesh, Agent Type Id, NavMesh Area Mask, Area Center.Y і Height Tolerance. |
| Estimated samples завеликі | Збільш spacing або зменш область. Ліміт перевіряється до запуску. |
| Усе червоне, відстані ∞ | Не знайдено відповідних цілей. Налаштуй masks, активні геометричні об'єкти та POIs або вимкни непотрібні модулі. |
| Усе зелене, cover distance майже 0 | Перевір, чи не включена суцільна земля або великий prefab bounds, що накриває всю ділянку. |
| Overlay сірий | Модуль був вимкнений у момент аналізу. Увімкни та повтори Analyze Map. |
| Змінив thresholds, але колір не змінився | Потрібен новий Analyze Map. Display-кольори оновлюються одразу, measurement thresholds — після аналізу. |
| Density не дорівнює кількості мешів | Працює групування за prefab roots/GameObject та пошук до bounds. |
| Немає великих порожніх кластерів | Перевір Empty Traversal, усі ввімкнені додаткові умови, Minimum Cluster Samples і NavMesh-зв'язність. |
| Після Clear Analysis лишилася рамка | Це Area. Вимкни Show Area. |
| Не видно точок | Перевір Show Visualization, Show Samples, завершення аналізу, ракурс Scene View і display budget. Геометрія може перекривати overlay. |
| Cancel у Map Analysis залишив старі точки | Це очікувано: незавершений результат не замінює попередній. Для видалення натисни Clear Analysis. |
| Поле POI або exclusion спорожніло після рестарту | Завантаж відповідну збережену сцену. Якщо об'єкт видалений, признач новий. |

Якщо Console містить exception, збережи його повний текст разом зі статусом вікна та дією, яка його викликала. Це дозволить відрізнити помилку інструмента від непридатних вхідних даних.

## 15. Межі поточної версії

Scatter обмежений прямокутною областю та Target Object Count. Немає polygon area, spline placement, brush painting, biome rules, точних квот prefab або автоматичного розпізнавання доріг.

Map Analysis використовує Box Area, а не автоматичний Whole NavMesh. Це геометрична діагностика XZ. Великі об'єднані bounds, поверхи, навіси та геометрія над точкою можуть впливати на результати; masks і вибір області залишаються відповідальністю дизайнера. Порожні transforms не є interesting/cover geometry, якщо в них немає відповідних Renderer/Collider; для POI порожній сценовий transform придатний.

Немає автоматичного gameplay balancing, оцінки справжнього бойового cover, симуляції NPC, розрахунку часу traversal, runtime overlay, експорту звітів, збережених порівнянь аналізу або автоматичної оптимізації baked props. Інструменти прискорюють authoring і пошук ділянок для перевірки; фінальні рішення приймаються з урахуванням гри та композиції рівня.
