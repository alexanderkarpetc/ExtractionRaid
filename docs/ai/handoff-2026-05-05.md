### 2026-05-05 — Tier 8.x* (asset architecture rebuild)
**The big one.** User-driven design call: original payload/delivery prefab roles were inverted from intuition. Old: payload=barrel mesh, delivery=full weapon. New: payload=weapon BASE (handle, receiver), delivery=barrel insert.

**Asset architecture (NEW):**
```
Module_Payload_BallisticRound.prefab (root has Animator + WeaponView)
├── KickGroup (recoil kick target)
│   ├── PayloadBaseMesh
│   ├── DeliverySocket (where delivery instantiates at runtime)
│   └── RightHandGrip (IK target — kicks з weapon recoil)

Module_Delivery_Auto.prefab (no MonoBehaviours)
├── DeliveryBarrelMesh
└── MuzzlePoint (Y synced з ProjectileSpawnHeight)
```

5 prefabs total: 2 payloads × 3 deliveries. All generated by `Tools → Weapon Builder → Create Module Prefabs` menu. Uses primitive cubes + capsules with persistent .mat assets (gunmetal/cool-blue tints). Real art swap = drop-in replacement.

## Architectural rules to keep tight

- Systems must not call `App.Instance` (only `App.Instance.Player`/`RaidSession` allowed exception). Tunables travel via `RaidContext.*Config` structs, populated у `RaidSession.Tick`.
- State stores values + IDs only — no Unity object references (`MonoBehaviour`, `GameObject`, `Transform` etc).
- View/Presenter doesn't contain gameplay rules.
- Gameplay logic у stateless static systems.
- Weapon prefab structure invariants enforced by `WeaponPrefabStructureTests` — adding/changing prefab fields will likely break those tests, update accordingly.
